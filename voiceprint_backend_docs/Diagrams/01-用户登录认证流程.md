# 用户登录认证流程时序图

## 流程说明

用户通过前端登录界面输入用户名、密码和图形验证码，后端验证身份后返回 JWT AccessToken 和 RefreshToken，前端存储 Token 并用于后续所有 API 调用。系统同时支持通过 RefreshToken 刷新 AccessToken 以实现无缝续期。

## 时序图

```mermaid
sequenceDiagram
    autonumber
    participant User as 👤 用户
    participant Frontend as 🌐 前端应用
    participant API as 🔌 API 网关
    participant AccountService as 📦 账户服务 (AccountService)
    participant AuthService as 🔐 认证服务
    participant Database as 💾 数据库

    Note over User,Database: 获取验证码阶段
    Frontend->>API: GET /api/app/account/captcha-image
    API->>AccountService: 生成验证码图片
    AccountService-->>API: { img, uuid }
    API-->>Frontend: 验证码图片 + UUID
    Frontend->>User: 显示图形验证码

    Note over User,Database: 登录阶段
    User->>Frontend: 输入用户名、密码、验证码
    Frontend->>Frontend: 表单验证
    Frontend->>API: POST /api/app/account/login<br/>{ userName, password, uuid, code }
    API->>AuthService: 验证验证码 (ValidationImageCaptcha)
    AuthService-->>API: 验证码校验通过
    API->>AuthService: 验证用户凭证
    AuthService->>Database: 查询用户信息
    Database-->>AuthService: 用户数据
    AuthService->>AuthService: 验证密码<br/>生成 JWT AccessToken + RefreshToken
    AuthService-->>API: 返回双 Token + 用户名
    API-->>Frontend: HTTP 200 OK<br/>{ token, refreshToken, userName }
    Frontend->>Frontend: 存储 Token 到 localStorage

    Note over User,Database: 获取账户信息阶段
    Frontend->>API: GET /api/app/account<br/>Authorization: Bearer {token}
    API->>AccountService: 验证 Token 并获取账户信息
    AccountService-->>API: 返回用户、角色、菜单、权限编码
    API-->>Frontend: { user, roles, menus, roleCodes, permissionCodes }
    Frontend->>Frontend: 更新应用状态<br/>跳转到主页面

    Note over User,Database: Token 刷新机制
    Note right of Frontend: AccessToken 即将过期时
    Frontend->>API: POST /api/app/account/refresh<br/>{ refreshToken }
    API->>AuthService: 验证 RefreshToken
    AuthService-->>API: 返回新的 AccessToken + RefreshToken
    API-->>Frontend: { token, refreshToken }
    Frontend->>Frontend: 更新存储的 Token

    Note over User,Database: 后续请求（携带 Token）
    loop 每次请求
        Frontend->>API: 任意 API 请求<br/>Authorization: Bearer {token}
        API->>API: 验证 Token 有效性
        Note right of API: Token 有效则处理请求
    end
```

## 关键接口

| 接口 | 方法 | 说明 |
|-----|------|-----|
| `/api/app/account/captcha-image` | GET | 获取图形验证码（图片+UUID） |
| `/api/app/account/login` | POST | 用户登录，返回 AccessToken + RefreshToken |
| `/api/app/account` | GET | 获取当前账户完整信息（用户、角色、菜单、权限） |
| `/api/app/account/refresh` | POST | 通过 RefreshToken 刷新 AccessToken |

## 请求/响应数据结构

### 登录请求 (LoginInputVo)

```json
{
  "userName": "string - 用户名",
  "password": "string - 密码",
  "uuid": "string? - 验证码UUID (来自captcha-image)",
  "code": "string? - 验证码"
}
```

### 登录响应 (LoginOutputDto)

```json
{
  "token": "string - JWT AccessToken",
  "refreshToken": "string - 刷新Token",
  "userName": "string - 用户名"
}
```

### 账户信息响应 (UserRoleMenuDto)

```json
{
  "user": { "id", "name", "userName", "email", "phone", "icon", "sex", ... },
  "roles": [{ "id", "name", "code", ... }],
  "menus": [{ "id", "name", "path", "icon", ... }],
  "roleCodes": ["string"],
  "permissionCodes": ["string"]
}
```

## 认证机制

- **JWT AccessToken** — 主要认证凭证，短期有效
- **JWT RefreshToken** — 用于刷新 AccessToken，长期有效
- **OAuth** — 支持 QQ 和 Gitee OAuth 提供商登录
- **令牌传递** — QueryString (`?access_token=`) 或 Cookie (`Token=`)
