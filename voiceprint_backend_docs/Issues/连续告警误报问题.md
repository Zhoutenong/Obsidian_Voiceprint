# 连续告警误报问题

## 问题描述

设备状态因传感器波动导致频繁误报，产生大量无效告警记录，影响监控有效性。

### 症状

- 单次波动触发多个告警
- 短时间内同一设备重复告警
- 运维人员收到大量无效通知
- 告警疲劳导致真实问题被忽略

### 影响范围

- **模块**: ast-intellisub (设备监控), ast-voiceprint (声纹分析)
- **业务**: 设备健康监测、声纹异常检测
- **用户体验**: 告警通知泛滥

## 根本原因

1. **传感器噪声**
   - 环境干扰导致读数波动
   - 电磁干扰影响通信
   - 采样频率与信号变化不匹配

2. **阈值触发策略**
   - 单次超过阈值即告警
   - 无滞后机制
   - 未考虑持续性判断

3. **声纹分析误判**
   - 音频质量波动
   - 算法对噪声敏感
   - 短时异常被放大

## 解决方案

### 核心策略: 连续告警机制

**"连续五次告警才触发正式告警"** - 减少瞬时波动导致的误报

### 实现代码

#### 1. 声纹分析连续告警

```csharp
// VoiceprintAudioAppService.cs
if (!string.Equals(normalizedLabel, "运行正常", StringComparison.OrdinalIgnoreCase))
{
    // 连续五次次异常才判定为异常，前四条异常仍视作正常以减少误报
    var prevRecords = await _deviceAudioRecordRepository._DbQueryable
        .Where(x => x.MonitoredObjectId == input.MonitoredObjectId && x.Id != record.Id)
        .OrderBy(x => x.CollectedAt, OrderByType.Desc)
        .Select(x => new { x.RealAnomalyType })
        .Take(5)
        .ToListAsync();

    // 判断前4次是否都异常
    var consecutiveCount = prevRecords
        .Where(x => !string.Equals(NormalizeLabel(x.RealAnomalyType), "运行正常", StringComparison.OrdinalIgnoreCase))
        .Count();

    if (consecutiveCount < 4)
    {
        // 未达到连续5次，强制标记为正常
        normalizedLabel = "运行正常";
        record.RealAnomalyType = "运行正常";
    }
}
```

#### 2. 设备监控连续告警策略

```csharp
// AlarmStrategyBase.cs (示例基类)
protected async Task<bool> ShouldTriggerAlarmAsync(MonitoredPoint point, decimal currentValue)
{
    // 获取最近的5次检测记录
    var recentChecks = await _monitorPointRepository._DbQueryable
        .Where(x => x.MonitoredPointId == point.Id)
        .OrderByDescending(x => x.CheckTime)
        .Take(5)
        .Select(x => x.IsAlarm)
        .ToListAsync();

    // 判断是否连续5次告警
    var consecutiveAlarmCount = recentChecks.Count(x => x == true);
    
    return consecutiveAlarmCount >= 5;
}
```

## 配置选项

```json
{
  "Alarm": {
    "ConsecutiveTriggerCount": 5,  // 连续告警次数阈值
    "CheckInterval": 60,            // 检查间隔（秒）
    "SuppressSimilarAlarm": true,   // 抑制相似告警
    "AlarmCooldown": 300            // 告警冷却期（秒）
  }
}
```

## 机制详解

### 告警判定流程

```
┌─────────────┐
│  数据采集    │
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  阈值判断    │ ────── 正常 ────┐
└──────┬──────┘                  │
       │ 超限                   │
       ▼                        │
┌─────────────┐                  │
│ 连续性检查   │                  │
│ - 获取最近4次│                  │
│ - 判断是否异常│                  │
└──────┬──────┘                  │
       │                         │
       ▼                         ▼
┌─────────────┐          ┌─────────────┐
│ 连续5次异常? │ ─── 否 ──┤  标记正常    │
└──────┬──────┘          └─────────────┘
       │ 是
       ▼
┌─────────────┐
│  触发告警    │
│ - 记录告警   │
│ - 发送通知   │
└─────────────┘
```

### 关键参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `ConsecutiveTriggerCount` | 5 | 连续异常次数阈值 |
| `CheckInterval` | 60秒 | 每次检测间隔 |
| `AlarmCooldown` | 5分钟 | 同类告警冷却期 |

## 预防措施

### 1. 数据质量优化

- 传感器数据滤波（移动平均、中值滤波）
- 异常值剔除（3σ原则）
- 数据平滑处理

### 2. 告警抑制策略

```csharp
// 告警抑制逻辑
if (IsInCooldownPeriod(lastAlarmTime, cooldownSeconds))
{
    _logger.LogInformation("告警抑制：处于冷却期内");
    return;
}

if (IsSimilarToRecentAlarm(alarmType, threshold))
{
    _logger.LogInformation("告警抑制：与近期告警相似");
    return;
}
```

### 3. 分级告警

- **预警**: 连续 3 次异常
- **告警**: 连续 5 次异常
- **紧急**: 连续 10 次异常或严重异常

## 监控指标

- **误报率**: (告警总数 - 真实异常数) / 告警总数
- **漏报率**: 未检测到的真实异常数 / 总异常数
- **告警准确率**: 真实异常数 / 告警总数
